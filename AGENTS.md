# Local development

- Install Python dependencies: `python -m pip install -r server/requirements.txt`.
- On Windows, double-click `start.bat` to stop any previous instance of this project's server, install dependencies, launch the server, and open the page. Set `OPENJWB_NO_BROWSER=1` to skip opening the browser (for automated checks).
- Alternatively run the app manually: `python -B server/requestHandler.py`, then open `http://127.0.0.1:51896`.
- Check Python syntax without generating cache files: `python -B -c "import ast; ast.parse(open('server/requestHandler.py', encoding='utf-8').read())"`.
- Check JavaScript syntax: `node --check public/js/jwbauth.js`, `node --check public/js/cookie.js`, `node --check public/js/jwbpe.js`, `node --check public/js/ocanvas.js`, `node --check public/js/jwmake.js`, `node --check public/js/jwlive.js`, `node --check public/js/addon-host.js`, and `node --check public/index.js`.
- `jwbauth.js` owns the SJTU login sequence and directly connects to the QR WebSocket; `cookie.js` calls the generic Python bridge. The bridge only forwards requests to allowlisted SJTU hosts and maintains separate upstream cookie jars per browser session. Real QR login requires network access to SJTU login services. Password login is intentionally not implemented.
- Base modules are one-website-per-module. `jwlive.js` provides classroom-live APIs (v.sjtu.edu.cn), with its base UI grouped inside Canvas. Optional composite plugins live in `public/plugins/<name>/` and are registered as `kind: "addon"` with an entry URL in `public/misc/plugins.js`. `addon-host.js` lazy-loads them after the navigation divider and injects `auth` and public `services` (Canvas/live APIs). Reusing public login/business APIs is allowed; dependencies on base-module DOM, buttons, private entry state, or enabled switches are not. Core modules must not statically import plugin assets or automatically log in to plugin-private services. Disabled/missing plugin assets must not prevent core startup. See `public/plugins/README.md`.
- Continuous frames use `services.live.watchLiveFrames()` and `/api/bridge/live/watch` (start/next/stop long polling). `server/hls_monitor.py` remains an independent reusable HLS/FFmpeg/QR component and standalone CLI: no openJWB imports, login, course logic, or SJTU hosts. Keep application authentication and signed-URL resolution in the request-handler adapter. Recognition precedes image publication; consumers can use the delivered QR without grabbing a second frame. See `server/HLS_MONITOR.md`.
